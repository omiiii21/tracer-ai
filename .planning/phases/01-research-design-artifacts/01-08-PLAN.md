**Step 2 — Spawn the Explore sub-agent with the locked prompt.**

Use the Task tool with `subagent_type: "Explore"`. The prompt is the **enhanced version below** — it extends the RESEARCH.md §"Verification Sub-Agent Design" template with two additions required by this plan's acceptance criteria: (a) a mandatory `Cited files:` line per answer and (b) the `AGENT_REPORT: PASS` / `AGENT_REPORT: FAIL: <reason>` ending format.
```
You are a fresh agent onboarding to the tracer-ai project. Read ONLY files under /docs/.
Do NOT read /CLAUDE.md, /tracer-ai-foundation-prd.md, /About.md, /.planning/, or any source
code. If you cannot answer a question from /docs/ alone, say "Insufficient documentation —

answer, also list the /docs/ file path(s) you read to construct the answer (under a
"Cited files:" line — this is non-negotiable; an answer with no cited files counts as a
guess and will be marked FAIL).

Q2. How does data flow through the system end-to-end for a typical chat request?
Q3. What is the trace schema — list the spans, key attributes, and where full prompt/response payloads are stored.
Q4. What API endpoints exist and what is each one's purpose?
Q5. What does the UI look like — list the routes, key components per route, and the click-through navigation between them.

Return: a single response with all 5 answers labeled Q1..Q5, each followed by its
"Cited files:" line. End with one of: "AGENT_REPORT: PASS" (you found everything in
/docs/) or "AGENT_REPORT: FAIL: <comma-separated list of missing items>".

If at any point you found yourself needing to read a file outside /docs/, stop and
report which file you needed and why — that is a documentation gap to surface, not a
reason to widen scope.
```

Capture the sub-agent's complete response verbatim.

**Step 3 — Score each of the 5 answers against the locked pass/fail criteria.**

Score from RESEARCH.md §"Pass/Fail Criteria" (lines 818-826). For each question, write a Status: PASS or Status: FAIL with reasoning:

- **Q1 PASS** requires the answer mention all of: (a) RAG chatbot, (b) observability product thesis (or equivalent — "AI-native observability is the product"), (c) per-stage trace inspection, (d) Claude API docs corpus.
- **Q2 PASS** requires the answer describe: Browser → FastAPI → pipeline (retrieve → prompt_assemble → llm_call) → response → async eval branch via BackgroundTasks → eval span as child of rag.request via OTel context snapshot.
- **Q3 PASS** requires the answer list all 5 spans (`rag.request`, `rag.retrieve`, `rag.prompt_assemble`, `rag.llm_call`, `rag.eval`) AND mention the `feedback.user` event AND state that full prompt/response payloads live in the `span_payloads` JSONB side table (NOT span attributes).
- **Q4 PASS** requires the answer list at least 6 of 7 endpoints — `POST /chat`, `POST /feedback`, `GET /traces`, `GET /traces/{id}`, `POST /admin/ingest`, `GET /admin/corpus`, `PATCH /admin/chunking-config` — each with a one-line purpose.
- **Q5 PASS** requires the answer list all 5 routes (`/chat`, `/dashboard`, `/dashboard/traces/{id}`, `/dashboard/queue`, `/admin`) AND mention specific component names (Card, Table, Tabs, AreaChart, KpiCard, etc.).

Each PASS also requires: the agent's `Cited files:` line includes at least one file under `/docs/` AND the agent did NOT report needing to read outside `/docs/`.

Mark FAIL on any of: missing required elements above, agent's `AGENT_REPORT` line says FAIL, agent reports needing files outside /docs/, or `Cited files:` line is missing for that question.
