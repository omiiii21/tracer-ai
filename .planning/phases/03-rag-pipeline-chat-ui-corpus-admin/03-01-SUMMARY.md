## Decisions Made

- **voyageai pin tightening (T-03-01-04):** widened range `>=0.3,<1.0` was a supply-chain risk; tightened to `>=0.3.0,<0.4.0` per the plan's threat-model mitigation. Phase 3 still installs the same minor series Phase 2 pinned.
- **sentence-transformers as `[offline]` extra:** the plan explicitly directs this. Default `pip install -e .` no longer pulls ST; only `pip install -e ".[offline]"` does. This decouples Phase 2's Docker boot path from a 1.5 GB transformer dep that isn't used by the live chunks table (it's a 768-dim model; the table is VECTOR(1024)).
- **StreamEvent as plain union, not Pydantic v2 discriminator field:** the plan permitted either. Chose plain `TextDelta | Final` (TypeAlias style) because StreamEvent is yielded directly from `LLM.stream()`, not nested inside another Pydantic model — the discriminator is enforced by the runtime tagged literal on each variant. If a downstream plan embeds StreamEvent inside another Pydantic model, it can switch to `Annotated[..., Field(discriminator="kind")]` at the embed site without changing this module.
- **ChunkingConfigPatch alias of ChunkingConfig:** the plan said "alias OK". docs/api.md §"PATCH /admin/chunking-config" specifies optional fields, but the canonical TS in UI-SPEC §8 has both fields required. To satisfy both, we treat the PATCH as full-replacement of `{chunk_size, overlap}` (atomic shape). Future-proofing toward optional fields can be done with an `Optional[ChunkingConfig]` wrapper.
- **`IngestRequest = IngestSourceRequest | IngestUrlsRequest`:** plain typing union, not a Pydantic discriminated union, because the two variants have non-overlapping field names (`source` vs `urls`) so FastAPI/Pydantic can disambiguate at parse time without an explicit discriminator field. Route-layer validation will reject bodies that present neither or both fields per docs/api.md §"POST /admin/ingest".

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] SDK-isolation test produced false positive on its own anti-pattern doc string**

- **Found during:** Task 1 (RED → GREEN transition for tests/test_rag_protocols.py)
- **Issue:** The naïve `"import voyageai" in src` substring check matched the literal phrase inside the protocols.py module docstring that documents the ban. The test failed even though no real import existed.
- **Fix:** Added a docstring-aware helper `_find_real_import_lines()` that parses the source into (in-docstring, in-comment, code) regions and only flags lines whose stripped form starts with `import {module}` or `from {module}`. Same helper applied to `types.py`.
- **Files modified:** `tests/test_rag_protocols.py`
- **Verification:** All 14 tests pass; the helper correctly skips docstring blocks bracketed by `"""..."""`, single-line docstrings (`""" ... """`), and `# comment` lines.
- **Committed in:** `e543308` (Task 1 commit)

**2. [Rule 1 — Bug] Over-specific structlog logger type assertion**

- **Found during:** Task 2 (test_writer_uses_structlog assertion)
- **Issue:** `isinstance(mod.log, structlog.stdlib.BoundLogger | structlog.BoundLoggerBase)` was False because `structlog.get_logger()` returns a `BoundLoggerLazyProxy` until first use — neither of those concrete classes.
- **Fix:** Switched to a duck-typed contract check: `callable(mod.log.info)` plus a structural `mod.log.__class__.__module__.startswith("structlog.")` belt-and-suspenders. The test now asserts the actual contract (`.info(...)` is callable; the object originates from structlog) without coupling to internal class hierarchy.
- **Files modified:** `tests/test_writer_protocol.py`
- **Verification:** All 7 tests pass.
- **Committed in:** `dc9bd74` (Task 2 commit)
